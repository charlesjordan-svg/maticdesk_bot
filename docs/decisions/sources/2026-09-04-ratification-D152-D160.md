## One dependent item, proposed not ratified — D202

**D157's step-up list needs one addition, and it is a new entry rather than an edit.**

The register does not silently rewrite a ratified decision's text, so this is proposed as **D202**
rather than folded into D157:

> **D202 (proposed).** Creating or modifying a `vendor_access_grants` row requires step-up
> re-authentication.
>
> **Reasoning:** D144 identifies vendor staff as the highest-privilege position in the system, and
> D153/D154 make vendor access a time-boxed grant the customer enables. Granting it is therefore a
> more consequential action than the policy changes and IdP configuration already on D157's list,
> and it was omitted from that list by oversight rather than by decision.
>
> **Note:** D157's set was a judgment call, not a derivation from anything. The `step_up` column is
> indifferent to its contents. The full list after D202 would be: fleet-wide device revocation,
> audit export, transcript access, policy changes, IdP configuration, and vendor grant
> creation/modification.

Needs Charles's yes or no. **B2 can proceed without it** — the `step_up` column already exists and
D202 only adds an entry to the set of actions that set it.

## Scope guidance for B2, not an amendment

**D158 (author ≠ approver) is inert in Phase 1 and B2 should not build for it.**

It governs catalog changes. D149 deferred catalog distribution out of Phase 1, so there are no drafts
to approve and nothing for the constraint to act on. It is the one decision in the set with no table
behind it, which is the correct signal.

It is ratified as a decision. **If B2 begins building an approval workflow, that is Phase 2 scope
arriving early** and should be stopped rather than absorbed.

## Also worth doing in the same pass

**Add the decision provenance convention to the migration.** Where a migration implements a decision,
say which one and what its status was at the time:

```sql
-- D153 (ratified 2026-09-04) — vendor access as a time-boxed grant
create table vendor_access_grants ( ... );
```

Two reasons. A reader of `001-control-plane.sql` in six months can tell which shapes were bets and
which were settled. And the next ratification pass can grep for provenance rather than
reconstructing it by hand — which is what this session had to do, and which is how Task 1's finding
surfaced at all.
